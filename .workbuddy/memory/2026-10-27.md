# 2026-10-27

## 修复：qqbot 群消息 / 群 @ 消息仍重复处理

- 上一版按 `event.sub_type === 'at'` 分流，但该字段在生产环境恒为 `'normal'`：
  `Message` 基类构造时 `this.sub_type = 'normal'`；`em()` 里 `Object.assign(payload, { ..., sub_type: 'at', ...payload })`
  末尾又把事件对象自身的 `sub_type` 展回去覆盖掉。类型声明也只允许 `direct|friend|temp|normal`。
- 改为「让出 + 认领」：`onGroupMessageIn` 先 `await Promise.resolve()`；`onGroupAtMessageIn` 在第一个 `await`
  之前把事件加入 `claimedByGroupAt`（WeakSet）。`em()` 的 emit 循环是同步的，所以 `.at` 一定会在
  group 的微任务醒来之前完成认领；没有 `.at`（已授权）时 group 照常处理。
- 验证：沙箱模拟 SDK 同步派发 + 真实执行 `/neonaic:help`，**7 条断言全过**；反向验证（去掉认领）稳定
  复现「两个回调各跑一次、命令回复 2 次」。
- 附带收益：未授权场景下不再由 group 先 dispatch 一个 `cancelable: false` 的事件，限流器只会看到一次可取消的
  消息事件。
