## 实施：内核生命周期管理器（常驻问题）

**现象**：没有启用任何拓展时内核不常驻。两个独立根因叠在一起：

1. `main.js`（`0098631` 引入）在 `bootstrap()` **没有 await** 的情况下紧跟 `process.exit(0)`。异步启动被截断：日志停在「正在加载可用拓展」，退出码却是 0，`exit` 钩子把 PID 锁也清掉，看起来像「启动成功但立刻没了」。
2. 保活定时器藏在 `cliProcessor.startCLI()` 里。它本身能持住事件循环，但：
   - 非 TTY（systemd / 容器 / 重定向）时 `startCLI()` 提前 return，保活跟着一起没；
   - `stopCLI()`（本意只是收提示符）会把进程生命周期一起停掉。

**改动**：
- 新增 `src/system/lifeCycleManager.js`（导出 `neonaicLifeCycleManager`）：
  - 常量：`DEBUGING` / `ROOT_PATH` / `APP_NAME` / `APP_VERSION` / `PID_FILE_PATH` / `ANSI`；
  - 状态机 idle→running→stopping→stopped，`start()` 幂等、`stopped` 后 start 抛 IllegalState；
  - 保活：ref 状态 `setInterval`（1h 空回调），`startKeepAlive` / `stopKeepAlive` / `keepAliveActive`；
  - 关闭编排：`registerCloser`（LIFO）、`stop()`（不退出、幂等）、`shutdown()`（+5s 超时兜底 + exit）；
  - 顺带接管 PID 锁（acquire + `process.once('exit')` 兜底）与 SIGINT/SIGTERM。
- `entry.js`：常量改从管理器取；shutdown 委托给管理器；按 `platforms → extensions → cli` 注册 closer（执行顺序 CLI → 拓展 → 平台 → PID）；不再自己管 PID 与信号。
- `cliProcessor.js`：删掉保活定时器，`stopCLI()` 只收提示符。
- `main.js`：`await entry.neonaicEntry.bootstrap()`，删掉 `process.exit(0)`。
- `extensions/twenty-four-points/src/entry.js`：补 `getAllSessionUser` 的 import（onDisable 里用了却没导入，新 closer 一上来就报错）。

**验证**（`/tmp/lifeverify` 沙箱，`platforms: []` + 空 `extensions/`，stdin 为 `/dev/null`，均已清理）：
- 新版 `main.js`：5s 后仍存活，SIGTERM → 4 个 closer 全成功、PID 锁释放、exit 0；
- 旧版（WIP `process.exit(0)`）：4s 内自退，exit 0，日志停在「正在加载可用拓展」；
- 仅调 `L.start()` 的空进程：3s 后仍存活（证明保活本身足够）；
- 重复实例：第二实例 exit 1 + `[FATAL] 检测到已有实例正在运行`，第一实例与锁不受影响；
- 真实 6 个拓展（无平台）：SIGINT → 4ms 关闭，`unloadAll` 无卡顿；
- `neonaic:stop` 命令路径：`收到 COMMAND` → exit 0；
- 卡死的 closer：5s 后强制 exit 1（超时兜底生效）；
- 单元探针 30/30：常量、幂等、LIFO 顺序、失败隔离、`off()` 取消注册、`stopCLI()` 不影响保活、非法参数。

**一条踩坑记录**：`runStop` 里保活必须最后再停。先停保活再跑 closers 时，若某步只 await 已 resolve 的 Promise，事件循环会当场空转退出，后续关闭步骤静默丢失。
