## Joyous 拓展：按协议 V2 补全实现

**依据**：仓库里新出现的两份材料 —— `extensions/joyous/PROTOCOL-V2.md`（协议增量，唯一约定来源）
与 `extensions/joyous/NEONAIC-REQUIRED-CHANGES.md`（我方改动清单）。两者与对端 Joyous 仓库
`docs/neonaic/` 下的同名文件**逐字一致**。

**对端事实基础**（读了 `/Users/kdxiaoyi/Workspace/Repos/StreackMC/Joyous`，commit `93b52fb`）：
- Java 侧 `Neonaic/{bridge/{BridgeProtocol,BridgeSession,FrameCodec,UdsServer,HttpBridgeClient,NeonaicBridge},chat/*}` 已实现 V2。
- UDS：**Joyous 是监听方**（`AF_UNIX` ServerSocketChannel，Windows 不支持 ⇒ 回退 HTTP），
  accept 后**先发 hello**（`sendHelloFirst=true`）⇒ 本端必须是 `responder`。
- 常量逐项对齐：`v=2`、5 个新方法/能力、`not_bound`/`rate_limited`、`subname`、超时表。
- Joyous 的 `capabilities` 只有 `status.query` + `chat.broadcast`。
- HTTP 通用端点：对端 `connect.http.server-path`（缺省 `/neonai/invoke`），信封 `{id,method,payload}` → `{ok,id,payload}`。

**本轮改动**（全部在 `extensions/joyous/` 内，`src/` 一行未动）：

  业务闸三层：`bridge.allowedMethods` 配置白名单 → `joyous.bridge.business` 总闸（默认不授予）
  → `joyous.bridge.<method>` 显式 false 才拒绝。**与命令闸相互独立**。
- `identity.js`（新）：`profile → mcKey(uuid 优先) → { chatId, name?, boundAt }`，
  存 `config/saves/joyous-identities.json`（gitignore）。

  复用），客户端新增 `invoke()`（自带带超时的 POST——内核 `neonaicNetwork.fetch` 不吃 fetch init）。

  订阅内核 `neonaic:message` 做内播（按**执行者链 × 配置频道白名单**匹配，不硬编码平台前缀）；

**过程中发现并修掉的 3 个真实缺陷**：
1. **`protocol/codec.js` 的 `JoyousLineFrameCodec` 漏 `super()`** —— 用户 10-08 的
   `6c54114 refactor: 规范化项目Object命名` 给类加了 `extends JoyousNewable` 但没加 super；
   派生类构造里访问 `this` 会抛 ReferenceError ⇒ **UDS 链路从那天起整体不可用**
   （首次 `new JoyousLineFrameCodec()` 即抛）。这是本轮最重要的发现。
2. `dispatch.js` 调用**不存在的** `neonaicCommandServer.checkCommandPerms`
   （重构前旧名）⇒ 凡 joyous 派发到「声明了权限的命令」必抛 TypeError；改为
   `checkPermissionFromContext(BRIDGE_CONTEXT, meta.permissions, meta.permissionDefault)`。
3. `JoyousUdsLink` **没有 `notify()`** ⇒ `identity.changed` 事件静默发不出去；补上（失败返回 false，不抛）。

**自检**：`/tmp/joyous-sandbox/selfcheck.mjs` **63 项全过** + `loadercheck.mjs` 4 项全过。
- 手法：写一个**独立的**极简分帧假 Joyous（行为对齐 Java 实现：先发 hello、

### 本轮翻出的 2 个真实缺陷
1. **`uds.js` 的异步连接失败不发 `error` 事件**：Node 的 `net.connect({path})` 失败是**异步
   `emit('error')`**、不同步抛，而 `error` 只挂在同步 catch 路径上 ⇒ 「对端没启动」这个
   **最常见**的失败完全静默（文档承诺的事件收不到）。已在 socket `error` 回调里 `emit`。
2. **`config.js` 的 `bridge.ai.AIlist` 未把默认值交给 `getList`** ⇒ 字段缺省时得到 `[]`，
   被归一化层误判成「用户写了空值」并记 issue：**每次全新配置启动都误报一条**。已修。
