# 2026-09-15

## 加入指数退让看门狗与 /restart，并收紧 /stop 权限

用户口径（AskUserQuestion 四问）：**主程序过长时间没喂狗就直接杀然后重启**；退避**做成可配置**；
`/restart` 走**进程级重启**；`/stop` 与 `/restart` **只改权限声明**（本地 CLI 照旧跳过检查）。

### 1. 三个新文件

- `src/system/watchdog.js` — 主进程侧：读配置、按期喂狗、退避记账、`restart()`（供 `/restart` 用）。
- `src/system/watchdog.worker.js` — Worker 侧：持有 deadline、判定 stalled/recovered/killing、强杀并拉起新进程。
- `src/system/restartProcess.js` — 共用「以分离进程拉起自身」，只依赖 `node:child_process`。

**为什么判定非要开 Worker**：主线程被同步代码卡死时它自己的 `setTimeout` 同样不触发，
同线程看门狗永远发现不了「没喂狗」。Worker 跑在独立线程上，照样计时、照样能 spawn 与 SIGKILL。

流程：主线程每 10s `feed()` → 120s 没喂 → Worker 报 `stalled` → 等 `graceMs`(5s)+退避 →
期间恢复喂狗则报 `recovered` 取消，否则报 `killing`：**拉起新进程 → 释放 PID 锁 → SIGKILL 自己**。

### 2. 配套改动

- `pidManager.js` 加 `waitForHandover()`：新进程带 `NEONAIC_RESTART` 启动时，先等旧实例交出 PID 锁，
  否则会被 `acquirePidLock` 判成「已有实例正在运行」。
- `Logger.js` 加 `Watchdog` 通道（`getLogger().watchdog`）。
- `entry.js`：抽出 `closeAll()`（关 CLI + 释放平台，关闭与重启共用）；`shutdown` 先停看门狗；
  bootstrap 里接棒等待 + 启动看门狗；**调试模式不启动**（断点长时间阻塞事件循环会被误判成卡死）；
  新增 `/restart`；`/stop` 与 `/restart` 权限都收紧为 `[superadmin]`（原来的 `[[superadmin, "neonaic.commmand.stop"]]`
  是 OR，第二层数组里任一权限即可 → 已去掉）。
- `config/main.json` 加 `watchdog` 段（enabled/timeoutMs/feedIntervalMs/graceMs/backoffInitialMs/
  backoffMultiplier/backoffMaxMs/backoffResetMs），全部有默认值；`.gitignore` 加 `.neonai.watchdog.json`。
- 退避状态存项目根 `.neonai.watchdog.json`：`nextDelay(n)` = 1s×2^(n-1) 封顶 5min；
  稳定运行超过 `backoffResetMs` 自动归零；人工重启清零计数。Worker 强杀那条路也会累加计数。

### 3. 过程中踩到的三个真问题（都已修）

1. **Worker 里的 `process.argv` 被改写**成 Worker 自己的入口（`['node','…/watchdog.worker.js']`）——
   于是强杀路径「拉起」的其实是 Worker 文件，一进去就抛错退出。修法：主线程把 `argv` 显式放进 `workerData`，
   `spawnReplacement(argv)` 显式接收（并拒绝空 argv，否则会 spawn 出一个裸 `node` 进 REPL）。
2. **Worker 会继承 `execArgv`**，而 `--input-type` 对文件入口的 Worker 非法 → Worker 直接启动失败、
   看门狗静默失效。修法：建 Worker 时过滤 `--input-type`/`--eval`/`--print`。
3. **Worker 里不能 import `pidManager`**：那条链会经 `NeonaicNewableError → chore → confManager`
   把 Logger 与 NeonaicConfig（含配置监视器）整套拖进 Worker。改为内联 6 行 `fs` 操作释放锁。
