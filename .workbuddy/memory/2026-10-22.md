## 修复：`utils/math.js` 表格解析的表头歧义（用户要求，不提交）

- 背景：`NeonaicTable`/`NeonaicMatrix` 是用户新写的未提交代码（HEAD 里是 +0 行，工作区 +689），唯一消费者是未跟踪的 `registerUtilsSupport.js`（`new NeonaicMatrix(data, 'csv', {cols, rows})`，纯数字无表头）。
- 原有歧义：Markdown/CSV 一律把首行当数据，标题必须由 `option.colTitle` 手工给；于是 GFM 表格的表头行会**既当标题又当数据**，而给了 `option.colTitle` 时表头行仍留在数据里 → 同一份标题出现两次。
- 新语义：
  - 新增 `option.header` ∈ `true|false|'auto'`（默认 auto），仅对 csv/markdown/array[] 生效。**auto 只在 Markdown 上推断**（`splitMarkdownTable` 改为返回 `{rows, headerDetected}`，分隔行紧跟首行 ⇒ 首行是表头）；CSV/array[] 默认无表头（CSV 首行无语法线索，猜错会吞掉真实数据）。
  - **冲突裁决 = option 优先**：文本源有表头 + `option.colTitle` ⇒ 标题用 option，表头行仍从数据移除；object 源的键序与 option 标题序冲突 ⇒ 按 option 重排原始数据。
  - `colTitle`/`rowTitle` 改由 `titleList()` 归一，接受单值（原先 `Array.isArray` 会把 `colTitle:'A'` 静默丢弃）。
  - 列数取「数据最大宽度」与「表头行宽度」的较大者 —— 修掉「只有表头、没有数据行」被算成 0 列、标题被截成 `[]` 的边界 bug。
  - `toCsv()` 补 `@apiNote`：输出标题行后重新解析必须显式 `header: true`（文档层面消除往返歧义，未改实现）。
- 验证：`/tmp/tblverify` 沙箱（已清理）27 条断言全过（Markdown 有/无表头、CSV 默认与显式、array[]、三种冲突、object 重排、单值标题、rows/cols 冲突、矩阵两条路径、非法 header、往返）；另有边界脚本覆盖空表 / 只有表头 / ragged / 引号字段。
- **顺带发现并已修**：用户新加的 `import { NeonaicNewable }` 放在 math.js 首行，使本文件成为既有 ESM 环（NewableClass ↔ Error ↔ chore → confManager → NeonaicConfig → NewableClass）的入口，**直接 `import math.js` 必 TDZ 崩**（用 `git show HEAD:src/utils/math.js` 对比确认 HEAD 不复现）。已把该 import 移到 error/chore 之后并加注释说明原因。
- **发现但未修（只报告）**：`toCsv()` 转义错（转义 `|` 而非 RFC4180 的 `,`/`"`，`[['a,b']]` 导出成 `a,b` 再解析变两格）；`NeonaicMatrix.rank` 恒 NaN；`registerUtilsSupport.js` 的 `inverse().toString('csv')`（参数无效）、`matrix.signature()`（不存在，应为 `singular`）。

## 修复：qqbot 未授权「获取全部消息」时的重复执行 / AI 缺失（amend 702016d）

- 用户要求把这次修复 **amend 进 `702016d`**（"该提交没有实质解决问题"）。
- **根因（读 SDK 源码得到，不是猜）**：`qq-official-bot/lib/client.js` 的 `em()` 把事件名按 `.` 拆开、**逐个前缀 `emit`**。
  所以一帧 `GROUP_AT_MESSAGE_CREATE` 会依次触发 `message` → `message.group` → `message.group.at`，
  两次回调拿到的是**同一个 payload 对象**、顺序固定，与监听器注册顺序无关；`GROUP_MESSAGE_CREATE`（已授权）只到 `message.group`。
  `em()` 还会预先在 payload 上写 `sub_type`，`.at` 帧此处为 `'at'` —— 这就是判别依据。
- 于是之前的两条路都是错的：两个回调都处理 → 命令 `exec=2`、广播 `dispatch=2`；用先到先得的锁（`neonaicused`/WeakSet）
  → `exec=1` 但 `resolveReply=0`，@ 闲聊直接 `reply=0`（零回复，正是 702016d 声称修好其实没修的那个 bug）。
- 修法：`sub_type === 'at'` 时 `onGroupMessageIn` 直接让出，由 `onGroupAtMessageIn` 独占 `cmd + AI`；锁整体删掉。
- 验证：`/tmp/qqverify` 沙箱（已清理）**11 条断言全过**。做法是复刻 `em()` 的派发（同一个 event 对象按前缀顺序调两个处理器），
  并打桩 `executeCommandSilent` / `resolveReply` / `eventBus.dispatchEvent` 计数；`pp` 必须用 `NeonaiPlatform` 真子类
  （`NeonaicMessageEvent` 构造有 `instanceof` 校验），`PlatformManager` 需先 new（`entry.js` 顶层就 `registerPlatform`，且要给它一个带 `main` 的 logger 桩）。
- 三向对照实测（同一套桩，`exec/resolve/dispatch/reply`）：@ + 命令 无锁 `2/1/1/2`、锁 `1/0/0/1`、修复 `1/1/1/1`；@ + 闲聊 `0/1/2/1`、`0/0/1/0`、`0/1/1/1`。

## 实施：science 高精定点引擎（第二轮，已完成）

- 用户拍定：**完整引擎**（四则 + 幂 + 根 + 对数），精确度按**小数位数**（定点 scale）。
- 表示：内部 = `真实值 × 10^scale` 的 BigInt；`scaledToStore` 去尾零后返回 `{mantissa, exponent}`（能放进安全整数时用 number）。
- 运算：加法直加；乘/除/模按 scale 舍入（`bigRoundDiv` 半值远离零）；整数幂快速幂；n 次根用 integerRoot（牛顿 + 末位修正）；`ln` 用 atanh 级数（归一化到 [1,10)，折半到 [1,2)，y≤1/3），`lg` 换底。
- 关键细节（都踩过）：
  - 根号多算一位再 `/10` 四舍五入，否则末位恒偏小；移位指数是 `scale*(n-1)+n`，写成 `(scale+1)(n-1)` 会让结果整体小 10^(1/n)（√2 → 0.4472）。
  - 取模必须 `a - (a/b)*b`（两个操作数同 scale，比值就是 a/b）；先乘 10^scale 再除会丢一位。
  - `lg` 的分子分母都要取到工作精度再相除；各自先舍入会漂（`lg8/lg2` → 3.00000000000000000003，虽在末位 ulp 内但难看）。
  - `decimalToString` 的科学记数法阈值要与 JS 一致（小数点后 > 6 个 0），否则 h*NA 会打成 0.000000000399…。
- 验证：`/tmp/sciverify` 沙箱（已清理）**62 条断言全过**：四则逐位比对（1/3、2/3 进位、1/7、0.1+0.2=0.3）、π/e/φ 40 位（末位进位）、π/2、NA/k/h/h*NA/NA*k*300、幂与根（含 ∛-27、4√16、√-4）、ln2/ln10/ln(0.5)/lg2/换底、取模符号、science 取值校验、浮点路径回归、store⇄number⇄string。AI 工具另测 8 条（含 precision 40 与浮点混跑）。
- 又一次「先怀疑期望值」：φ 第 30 位、h*NA 的量级、lg8/lg2 的末位，三条 FAIL 里有两条是我算错/断言错，只有 lg 那条是真·精度问题（已改成按 ulp 断言并写进文档）。
