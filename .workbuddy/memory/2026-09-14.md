### 复核确认（脚本 `/tmp/wordle-bugs.mjs`、`/tmp/wordle-probe2.mjs`）

**唯一的「活」bug：字母判定不数份数（高）**
`this.answer.includes(iletter)` 只判「答案里有没有」，不扣减已用份数 → 同一字母被反复标黄/绿。
实测 3000 对随机组合里 285 对（9.5%）反馈错误。玩家视角的干净例子：

- 答案 `posse`（p×1 o×1 s×2 e×1），猜 `bokos`
- 模块给 `⬜🟩⬜🟨🟨`（B白 O绿 K白 **O黄** S黄）
- 正确应为 `⬜🟩⬜⬜🟨`（第 4 位的 O 该是白）——答案里只有一个 o，已被第 2 位的绿用掉
- 影响：玩家会去找一个不存在的第二个 O；困难/极限下还会被「黄色必须继续使用」逼着继续用 o
- 修法：先算答案里每个字母的剩余份数，`right` 扣一份、`pos_wrong` 再扣一份，份数用尽才是 `missing`

**隐患（当前任何命令路径都摸不到，属公开 API 上的地雷）**
- `usable` 关闭后 `guess()` 仍作答（无守卫）
- `set usable` 的 `throw` 漏 `new` +「重复关闭」会抛 → `clearSession` 非幂等安全、猜中答案会抛、超时回调会抛出未捕获异常并留下僵尸会话
- `timeouts` 过期后不清理（陈旧 `timeoutId`）
- `guess()` 用 `v.length` 而非归一化后的 `input.length`
- `history` / `historyOfResult` 按引用外泄
- `neonaicMath.random` 用 `Math.round`（在 `src/utils/math.js`，两端概率减半）

**重要修正**：上次我把第 2 条（`usable`/`set usable`）标成了「高」，这次专门验证了
**是否存在命令可达的路径** —— 没有。`newSession` 建于 `usable=true`，赢/输/放弃等路径都是
「先 `clearSession`（会 `delete` 并清定时器）再写私有字段」，所以 Map 里不会出现
`usable=false` 的会话；要造出僵尸会话必须先有人从外部写 `session.usable = false`。
所以它应记作**潜在**缺陷而非线上问题。

### 1. `guess()` 的字母判定改成按份数结算

两趟：第一趟把位置正确的绿格认领掉（扣减份额）；第二趟对剩下的位置按剩余份额判黄，份额用尽保持白。
`let result = []` + `push` 改成 `new Array(len).fill(missing)` + 下标赋值，因为需要两趟。

### 2. 连带必修：`#constraints().white` 要剔掉已证存在的字母（关键因果）

**修完份数判定后，`missing` 不再等价于「答案里没有这个字母」**——`posse` 猜 `bokos` 时第 4 个 `o`
被标白，但 `o` 确实在答案里，只是份额被绿格用光了。而极限模式的「白色字母不得出现」原本依赖
「白 ⇒ 不在答案里」这个（旧 bug 下才成立的）前提，于是会去封禁正确答案里的字母。

不复现不知道：改完第一处后跑 400 局极限模式，**56 局出现「答案本身违反约束」= 无解**。
修法是在 `#constraints()` 末尾把 `green.values()` 与 `yellow[].letter` 里的字母从 `white` 中删掉——
只用反馈信息，不偷看 `this.answer`。顺带让 `/wd h` 的「已排除字母」提示语义变正确（只列真正不在答案里的）。

### 顺手报告的遗留（未改）

`set usable` 仍非幂等：已关闭再设 false 会抛 `NeonaicIllegalStateError`。因此
① `clearSession` 对这类会话会抛（调用方无法预料）；
② `onDisable` 里的 `getAllSessionUser().map(clearSession)` 会在第一个抛错处中断，后面的会话清不掉。
两者都需要「先有人从外部写 `session.usable = false`」才触发，当前命令路径摸不到。
根因修法是让 setter 幂等（当前值等于目标值就直接 return）。

## 提交前复核：发现 setter 的修法偏了（已随本次提交入库，未擅自改回）

用户随后自行在 `set usable` 顶部加了一行 `if (!v) return;` 并暂存，结果与预期相反：

- `usable = false` 变成**静默空操作**（不再抛错，但也没真的关闭）
- 第 89 行的 `throw new NeonaicIllegalStateError(...)` 成为**不可达死代码**（`!v` 已在上一行返回）
- `clearSession` 里的 `sessions.get(u).usable = false;` 跟着失效，`guess()` 的 `!this.#usable` 守卫失去外部触发来源

影响面实测：难度功能回归 **64/64 仍全通过**（赢/输/放弃/超时四条路径都仍会把会话从 Map 删除，玩法无感）；
针对性验证 20 项掉到 17 项，失败的 3 项（`#2 关闭后拒绝作答` / `#3 重复关闭的抛错类型` /
`clearSession 对已关闭会话的幂等性`）全部由这一行引起 —— 它们是**以「关闭生效」为前提**写的。

正确的幂等写法应是「当前值已等于目标值才 return」：

```js
set usable(v) {
  if (this.#usable === !!v) return;        // 幂等：状态没变就直接返回
  if (!v) { this.#usable = false; return; } // 关闭
  throw new NeonaicIllegalStateError("Wordle 作答已关闭，无法再次恢复");
}
```

已在最终答复里把这条连同补丁一起交给用户，由他决定是否采用（未擅自改写其暂存内容）。

### 1. `src/utils/math.js`

- 新增 `calc(expr, options)`：递归下降求值。**参数不能叫 `eval`** —— ESM 恒严格模式，`function calc(eval, ...)`
  会直接 `SyntaxError`，故写 `calc(expr, options)`。
  优先级 加减 → 乘除模 → 一元正负 → 幂(右结合) → 根号 → 括号/数字；除号 `/` 与 `÷` 等价、乘号另有 `×`/`·`、
  全角符号与全角数字自动折算、`**` ≡ `^`。三项可选特性默认 false。
  根号次数识别：**紧跟根号的整数（含上标）一律当次数**，于是 `2√9` = 3 而不是 `2*√9`；`^3√8` 的 `^` 是次数，
  但 `2^3√8` 里 `^` 前面有值，仍按幂解析。语法错误抛 `NeonaicIllegalArgumentError`（带位置），
  除数为零 / 负数开偶次方抛 `NeonaicArithmeticError`。
- 补完 `dfs24solution`：连 user 骨架里 `throw NeonaicIllegalArgumentError(...)` 漏 `new` 一并修掉。
  去重是 `+`/`*` 先按字典序规范两个子算式再拼接（消交换律重复），`-`/`/` 两种顺序都留，最后 Set 去重、
  剥掉最外层多余括号。
- **正确性靠文献值校准**：1–13 全部 1820 种牌型 → 1362 有解 / 458 无解（25.16%），与公开结果**完全一致**；
  解数最多的一手 `1 4 8 12` = 98 条（耗时 550ms 全量枚举）。
- 顺带修 `random`：原 `Math.round(Math.random()*(max-min)+min)` 让 **min/max 各只有一半概率**
  （wordle 首尾单词、24 点 A 与 K），改成 `min + Math.floor(Math.random()*(max-min+1))`。
