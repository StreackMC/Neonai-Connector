## `oai[].tools` 支持广义通配（修正注释与实现不符）

- 问题：`config/secret.json` 注释写「支持模糊匹配」，但 `matchToolPattern` 实际只做两种：带 `:` 的 fqn **完全精确**、不带 `:` 的按 name 跨命名空间**完全相等**。所以 `"ns:*"` / `"!ns:*"` 静默匹配 0 个（还进了 unmatched 提示）。
- 改法（`src/message/ai.js`）：新增 `globToRegExpSource(glob, starSrc)`（只把 `*` 当元字符，其余全转义；按 `split('*')` 分段转义再拼），`matchToolPattern` 按**第一个 `:`** 切成 `nsGlob` / `nameGlob` 两段分别转正则：命名空间段的 `*` → `[^:]*`（不跨 `:`），工具名段的 `*` → `.*`。省略命名空间时 `nsGlob='*'`，保持「不带前缀即跨命名空间」旧语义。
  - 结果语法：`"*"` / `"ns:*"` / `"*:name"`（≡ `"name"`）/ `"n*:a*"` / `"!ns:*"`；`"ns:"`、`"ns:a"` 仍不隐式前缀匹配。
  - 注册时 ns/name 都被规整为 `[a-zA-Z0-9_]`，段内无 `:`，所以按第一个 `:` 切分无歧义 —— 这也是这段实现的前提。
- 顺带：`ai tool test <ref>` 现在可能一次命中多个（`findTool` 复用同一匹配），改为命中多个时列出候选并报错，而不是静默执行第一个。
- 验证：`/tmp` 沙箱（rsync `src` + 软链 `node_modules`）里注册 3 个命名空间 / 5 个工具，19 条断言全通过；`node --check` 通过。
- 文档：`config/secret.json` 的 `tools` 注释按新语法重写，`resolvePatternList` / `resolveToolList` / `findTool` 的 JSDoc 同步。
