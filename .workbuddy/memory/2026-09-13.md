# 2026-09-13

## Wordle 拓展：新增难度系统 + 无对局语法糖 + 排除字母提示

用户提交了 `20dd9e4 feat: 新增命令/游戏 Wordle`（拓展结构已改为 `extensions/<name>/src/*.js`），随后要求为命令处理增加难度玩法。改动集中在两个文件（未提交）。

### 1. `extensions/wordle/src/session.js`

- 新增 `WordleDifficulty = { normal, hard, uhard }` 与 `resolveDifficulty(v)`（别名 → 规范名，未知返回 `null`）。
  - **刻意不收单字母 `h`**：它与查询历史的别名冲突，若解释为困难，「没有对局时输入 `/wordle h`」会意外开出一局困难游戏。接受的别名：`normal|n`、`hard`、`uhard|uh|ultrahard`。
- `WordleSession` 新增 `#difficulty`（getter/setter，setter 用 `resolveDifficulty` 校验后抛 `NeonaicIllegalArgumentError`）、`excludedLetters`、`lockedLetters` 两个只读视图。
- 新增 `#constraints()`：从 `#triesResult` + `#tries` 汇总 `{ green: Map<index,letter>, yellow: [{letter,index}], white: Set<letter> }`。**注意**：猜中那一行在 `#triesResult` 里存的是 `'right'` 字符串（用户自己的设计），等价于整行全绿，这里一并展开，否则会漏读。
- 新增 `#findViolation(input)` + 公开 `checkDifficulty(v)`（不消耗轮次、不记入历史，返回 `{reason, letter, index}|null`）。判定顺序：绿色位置 → 黄色必须使用 → （仅极限）黄色必须换位 → （仅极限）白色不得出现。
- `guess()` 在「已猜过」检查之后插入违规检查，返回 4 个新枚举之一；被拒的猜测不入历史、不消耗轮次。
- `newSession(user, timeout, difficulty)` 增加第 3 个参数，仅在该用户尚无会话时生效。

**为什么这些约束是安全的**：`missing` 的判定是 `!this.answer.includes(letter)`，所以 missing 永远真；`right` 也永远真。实测 3411 对样本中「把答案里有的字母标成 missing」= 0、「把位置不对标成 right」= 0。也就是说只有 `pos_wrong` 会**多报**，因此建立在 `missing` 之上的极限模式「白色字母不得再出现」不会误封正确字母。（`pos_wrong` 多报本身是下面的 bug 1。）

### 2. `extensions/wordle/src/entry.js`

- **参数解析重构**：原来 `function (...v)` + `let param = v.map(parseString).join('')`，导致 `/wd new hard` 被拼成 `"newhard"`，`new` 分支永远不触发。现在拆成：`sub = args[0]`（子命令只看第一个参数）、`param = args.join('')`（猜测仍支持 `/wd cr ane` 这种手滑）。
- `new [难度] [首个猜测]`：首参是难度则取第 2 参作首个猜测，否则把首参本身当首个猜测（普通难度）。`normal|hard|uhard` 之外还有 `n|uh|ultrahard`。
- **无对局语法糖**：`hard`/`uhard` → 以该难度开局；5 字母 → 普通开局并直接作为第一次猜测；其余（如 `stop`、`h`、`zzz`）→ 普通开局。
- 抽出 `play()` / `buildIntro()` / `buildWin()` / `buildLose()` / `buildViolation()`，减少重复；`buildHistory(session, withHint)` 的 `withHint` 只在 `/wd h` 时为真（用户只要求 h 带提示，普通猜测的回复不带）。
- 排除字母提示形如 `已排除字母：ｅ ｎ`（无则为 `暂无`）。
- 违规提示按**本局实际难度**加前缀（`困难模式：` / `极限模式：`），否则极限模式沿用困难规则时会误写成“困难模式”。
- 顺带修掉猜中文案结尾多出的一个 `”`（`…?q=${answer}”`，与开头「恭喜…」不成对）。

### 4. 踩到的脚本坑（重要）

1. **`Logger.js` 在模块加载时就劫持 `console.*`**，所以测试脚本里 `console.log` 全部静默 → 不能用。
2. **`process.stdout.write` 对管道是异步的**，进程被 kill 时缓冲丢失 → 输出为空。**用 `fs.writeSync(1, ...)` 同步写**。
3. **宿主里的相对 `import('./x.js')` 是相对脚本文件解析的**，不是 cwd。脚本放 `/tmp` 时必须用绝对路径，否则顶层 await 拒绝 + 自装的 `uncaughtException` 处理器把它吞掉 → 表现成「无输出、退出码 0」。
4. **`newSession` 会挂 `setTimeout`**，脚本不 `process.exit()` 就永远不会自然退出。

### 5. 顺带完成的代码审查（上一轮「看看有没有bug」的结论，已在当前代码上复核）

- **① 字母判定不数份数（高）**：`this.answer.includes(iletter)` 只判「有没有」，没扣减已用份数。实测 3000 对里 263 对（8.8%）给出错误的黄/绿标记，例：答案 `salve` 猜 `mulls` → 模块 `⬜⬜🟩🟨🟨`，应为 `⬜⬜🟩⬜🟨`。玩家会以为答案里有两个相同字母。修法：先算出答案里每个字母的剩余份数，`right` 消耗一份，`pos_wrong` 再消耗一份，份数用尽才是 `missing`。
- **② `usable` 关闭后 `guess()` 无守卫（中）**：`s.usable = false` 后 `s.guess('aahed')` 仍返回逐字母结果。
- **③ `set usable` 的 `throw` 漏了 `new`（高）**：`throw NeonaicIllegalStateError(...)` 实际抛的是 `TypeError: Class constructor … cannot be invoked without 'new'`。因为 `clearSession()` 与超时回调都会**无条件**写 `usable = false`，所以三条路径都会炸：`clearSession` 对手动关闭过的会话抛错（非幂等安全）、手动关闭后猜中答案抛错（判胜分支先调 `clearSession`）、超时回调抛错并把异常抛到进程级。修法：补 `new`，并把 setter 改成幂等（「已关闭再设 false」应静默通过）——内部写入点是无条件的，会抛错的 setter 本身就是设计问题。
- **③附**：超时回调抛异常后 `sessions.delete(u)` 没执行 → 会话变成僵尸，`hasSession` 仍返回 true。
- **④ `timeouts` 过期后不清理（低）**：回调自己不 `delete`，只有 `clearSession` 才清，`timeoutId` 会返回已触发的陈旧句柄。
- **⑤ `guess()` 用 `v.length` 而非归一化后的 `input.length`（低）**：`guess(12345)` 返回 `length_wrong`，本应 `not_a_word`（`parseString` 后是 5 位）。目前 entry.js 总先转字符串，属公开 API 层面的隐患。
- **⑥ `history` / `historyOfResult` 按引用外泄（低）**：外部 push 会改变模块内部数组，而 `buildHistory` 依赖两数组下标对齐。
- **⑦ `neonaicMath.random` 用 `Math.round`（低，在 `src/utils/math.js`）**：区间两端概率只有中间值的一半（实测 0 与 9 各约 49%/50%）。对本项目影响可忽略，但语义上「均匀随机」该用 `Math.floor`。
- 已在用户上一版自行修掉的：`MAX_TURN` 5→6 且轮次耗尽检查移到记录之后、胜局也写入历史（`triesLength` 不再少算 1）。构造器守卫漏 `new` 一处在我重写时被顺带补上。
