## 全量重构 src 模块导出为命名空间对象

- 需求：`src/` 下各模块不再分散具名导出，改为单个命名空间对象，如 `export const NeonaicCommandServer = {}`。例外：`Logger.js` 的 `parseString`。
- 命名规则（与用户确认）：`Neonaic` + 文件名 PascalCase。文件名与类名同名的（`NeonaicConfig.js` → `class NeonaicConfig`、`NeonaicNewableClass.js` → `class NeonaicNewable`）模块对象加 `Module` 后缀，类名保持不变，即 `NeonaicConfigModule`、`NeonaicNewableModule`。
- 另一个必要例外：`log4js_inject.js` 的 `configure`——log4js 把该模块当 appender 加载并要求顶层具名导出，故保留独立导出，只把 `putEmit` 收进 `NeonaicLog4jsInject`。
- 17 个模块的对象名：NeonaicCommandInterface / NeonaicCommandServer / NeonaicPermissionServer / NeonaicExtLoader / NeonaicLogger / NeonaicLog4jsInject / NeonaicAI / NeonaicMessageIn / NeonaicPlatformInterface / NeonaicPlatformManager / NeonaicPlatformUtils / NeonaicConfigModule / NeonaicNewableModule / NeonaicCliProcessor / NeonaicConfManager / NeonaicEntry / NeonaicPidManager。
- 调用点全部收敛为命名空间访问（`NeonaicLogger.getLogger()`、`NeonaicCommandInterface.COMMAND_ENUMS.X`）；类继承写作 `extends NeonaicNewableModule.NeonaicNewable`。
- `src/extension/extMgr.js` 是 0 字节空文件，未处理。

## 追加：getLogger() 也升为顶层语法糖

- 需求：调用点写 `getLogger()` 而不是 `NeonaicLogger.getLogger()`。
- 做法：`export function getLogger()` 顶层导出，并从 `NeonaicLogger` 对象里**摘除**（不做双重暴露，同上一节踩过的坑）；全量改写 52 处调用点，10 个文件的 import 按实际用法重写（`platformManager`/`entry` 仍保留 `NeonaicLogger`——它们还要用 `getDebugMode` / `setDebugMode` / `setConsoleHooks`）。
- 结果：`NeonaicLogger` 对象只剩 `{ setDebugMode, getDebugMode, setConsoleHooks, createLogger }`。
- 规律：项目接受「高频调用入口 = 顶层语法糖 + 不进对象」这一例外模式，目前有两个成员——`parseString` 与 `getLogger`。
- 验证：语法全通过、20 个模块 import 通过、`getLogger() === getLogger()` 单例一致、`resolveReply('/version')` 正常。

## NeonaicConfig 按 SConfig 补全边缘特性（Java → JS 移植）

- 参照物：`StreackLib/src/main/java/.../types/SConfig.java` + `docs/types/SConfig.md`。
- 现状：期间用户已把 `NeonaicConfig.js` 移到 `src/utils/`，模块对象全面改为 camelCase（`neonaicConfManager` / `neonaicCommandServer` / `neonaicAI` / `neonaicNetwork`），错误类体系落在 `src/utils/NeonaicNewableError.js`，`parseString` 单独抽到 `src/utils/text.js`。
- 用户定的三条口径：① 默认写入模式跟随 SConfig = AUTOSAVE；② LocalDate/LocalTime/LocalDateTime 统一映射为 `Date` 对象；③ BigDecimal 跳过（JS 无原生十进制类型）。
- 新增/补齐：`WRITE_MODES` 五种写入模式（含 `setWriteModeForever` 锁定）、自动重载（`fs.watch` 目录 + mtime 比对 + 间隔节流 + 出错退避，`watchFile` 兜底，句柄 `unref` 不阻塞进程退出）、`reload()` / `getRawData()` / `getFile()`、`isExist` / `isReachable` / `remove`、全套类型化 getter/putter（getShort 按 Java short 回绕、getFloat 用 `Math.fround`）、`getListOfString` / `getSection`（返回浅拷贝）/ `putSection`（可接另一个 NeonaicConfig）、`onAutoReloaded` / `onLoadFailure` 回调、链式调用、静态工厂 `fromObject` / `fromJSON5`（仅内存态 + 惰性临时文件）、原子写入（临时文件 + rename，同目录）、`_root_array` 根数组特例、`\.` 转义点号路径解析、编码可配。
